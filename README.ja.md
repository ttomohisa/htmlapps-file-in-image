# File in Image / 画像にファイルを埋め込む

[English README](README.md)

任意の1ファイルを画像の画素へ埋め込み、生成されたPNGからあとで元のファイルを取り出すブラウザーツールです。処理はブラウザー内で完結します。

> **現在の開発版:** v0.5.0。BKFI/BKFC形式はまだ開発途中で、v1の正式互換形式は固定していません。

## Features

- PNG / JPEG / WebP画像を入力、PNGを出力
- 任意の1ファイル、最大32 MiB
- BKFC全体が小さくなる場合だけGZIP
- 任意のPBKDF2-HMAC-SHA-256 + AES-256-GCMパスワード保護
- 保護時はファイル名・MIMEもファイル本体と一緒に暗号化
- 8×8ブロックで高ディテール領域を優先する適応埋め込み
- LSBを除外してSobel評価するため、埋め込み後も同じディテール順位を再現
- 画像全体のRGBスロット配列を作らず、ブロック単位で決定的にランダム配置
- 復元ファイルをSHA-256で確認
- 日本語 / 英語UI
- 実行時CDN・API・analytics・telemetry・ファイルアップロードなし
- `file://` 直接起動と単一HTML配布を前提

## 適応埋め込み

v0.5.0で新しく作る画像はBKFIの `embeddingMode=1` を使用します。最初の完全不透明214ピクセルは、従来どおりBKFI header専用です。bodyはそれ以外の場所へ埋め込みます。

画像を8×8ブロックへ分け、RGBの最下位1bitを除外した輝度にSobelフィルターを適用してディテール量を評価します。埋め込みで変更する最下位bitを評価から除外するため、取り出すときも同じブロック順位を再現できます。

高ディテールのブロックから、原則として必要bit数の約2倍の候補容量を確保し、その候補内でブロック順とRGBスロット順を決定的にシャッフルします。暗号化ありの場合はパスワードから導出したmaterialも配置seedへ使用し、暗号化なしの場合は画像ごとのrandom placement saltを使用します。

このランダム配置自体を暗号化機能としては扱いません。

## 後方互換

v0.2.0〜v0.4.0で作った `embeddingMode=0` の開発画像も引き続き取り出せます。v0.5.0で新しく作る画像だけ `embeddingMode=1` になります。

## パスワード保護

新規の暗号化画像はPBKDF2-HMAC-SHA-256 600,000回、16-byte random salt、AES-256-GCM、12-byte random IV、128-bit認証タグを使用します。BKFI header全体をAES-GCMのAADとして認証します。

パスワードはtrimやUnicode normalizationを行わず、localStorageやIndexedDBには保存しません。

## 重要な注意

高ディテール領域を優先しても、画像編集への耐性が付くわけではありません。リサイズ、トリミング、フィルター、JPEG/非可逆WebP変換、スクリーンショット、SNSやメッセージアプリによる再圧縮などで埋め込みデータは壊れる可能性があります。生成したPNGはそのまま保持してください。

v0.5.0では、Workerによるバックグラウンド処理と生成PNGの自動復元確認はまだ実装していません。

## Privacy

画像、ファイル、パスワードはブラウザーのメモリ内で処理します。`connect-src 'none'` を維持し、ユーザーデータを外部へ送信しません。ファイル内容やパスワードをブラウザーストレージへ保存しません。

## Development

現在の `htmlapps-template` の契約に準拠します。編集対象は `src/index.template.html` で、生成済み `dist` を直接編集しません。

build-standalone.bat
