# File in Image

[日本語版 README](README.ja.md)

File in Image hides one arbitrary file inside image pixels and recovers the original file from the generated PNG. Processing stays in the browser.

> **Release candidate:** v0.9.0. New output now uses compatibility format version 1. Development-format version 0 images from earlier releases remain readable.

## Features

- PNG / JPEG / WebP carrier input, PNG output
- One arbitrary payload file, up to 32 MiB
- GZIP when the complete inner container becomes smaller
- Optional PBKDF2-HMAC-SHA-256 + AES-256-GCM password protection
- 8×8 adaptive high-detail placement
- Blob Worker processing with progress / Cancel
- Mandatory generated-PNG recovery verification before Save
- SHA-256 verification of recovered source bytes
- Show / hide controls for password fields
- Compact selected-file drop zones that still accept Drag & Drop
- Japanese / English UI
- No runtime CDN, API, analytics, telemetry, or file upload
- Direct `file://` use and single-HTML distribution

## v0.9.0 format candidate

New v0.9.0 output writes:

- BKFI outer format version 1
- BKFC inner container version 1
- adaptive embedding mode 1

The decoder still reads version 0 output from v0.2.0–v0.8.0, including legacy sequential mode 0 and adaptive mode 1.

The adaptive placement algorithm, GZIP behavior, PBKDF2/AES-GCM parameters, 80-byte BKFI header, and 48-byte BKFC fixed header are unchanged.

If a post-RC blocker requires changing binary semantics, the format version should be bumped rather than reinterpreting version 1.

## Automated format regression

`scripts/check-format-regression.mjs` runs as part of the repository check and verifies version 0/1 compatibility, stable reserved-field validation, adaptive mode 1 round-trip, and legacy mode 0 extraction.

CI uses Node.js 24 for this check.

## Manual RC testing

Real browser/device regression is still required before v1.0. See:

- `docs/RELEASE_CANDIDATE_CHECKLIST.md`
- `docs/RELEASE_CANDIDATE_CHECKLIST.ja.md`

The checklist covers Chrome, Edge, Firefox, Safari, Android Chrome, iOS Safari, Japanese/English UI, file:// use, encryption, compression, legacy decode, mobile layout, and failure states.

## Important note

Automatic recovery verification confirms that the PNG generated by the app is recoverable at generation time. Later resizing, cropping, editing, JPEG/lossy WebP conversion, screenshots, or social/messaging recompression can still destroy the embedded data.

## Privacy

Images, files, passwords, Worker buffers, generated PNGs, and recovered bytes stay local. Runtime network access remains blocked with `connect-src 'none'`.

## Development

Edit `src/index.template.html`; do not hand-edit generated `dist` files.

```bat
build-standalone.bat
```

Repository verification:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-repository.ps1
```
