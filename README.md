# File in Image

[日本語版 README](README.ja.md)

File in Image hides one arbitrary file inside image pixels and recovers it later, entirely in the browser.

> **Current development version:** v0.2.0. The BKFI/BKFC format used here is a development format and is not yet the final v1 compatibility freeze.

## Features

- PNG, JPEG, and WebP carrier images
- Any single payload file up to 32 MiB
- PNG output
- Deterministic 1-bit RGB LSB embedding in fully opaque pixels
- SHA-256 verification of recovered payload bytes
- Capacity preview before embedding
- Drag and drop plus standard file pickers
- Japanese / English UI
- No runtime CDN, API, analytics, telemetry, or file upload
- Designed for direct `file://` use and single-HTML distribution

## Usage

### Embed

1. Select a carrier image.
2. Select the file to hide.
3. Confirm that it fits the displayed capacity.
4. Choose **Embed in image**.
5. Save the generated PNG.

### Extract

1. Open the **Extract** tab.
2. Select a PNG generated by this app.
3. The app extracts the payload and verifies its SHA-256 digest.
4. Save the recovered file.

## Important limitation

The hidden data is stored in image pixel least-significant bits. Resizing, cropping, editing, JPEG conversion, lossy WebP conversion, screenshots, or services that recompress the image can destroy the embedded file. Keep the generated PNG unchanged.

v0.2.0 does **not** yet provide encryption, GZIP compression, adaptive embedding, or generated-PNG self-verification. Those are scheduled for later development milestones before v1.0.0.

## Privacy

User-selected files are processed in browser memory. The app is designed with `connect-src 'none'` and has no runtime network dependency. File bytes are not stored in localStorage or IndexedDB.

## Development

This repository is based on the current `htmlapps-template` contract. Edit `src/index.template.html`; do not manually edit generated `dist` files.

Run on Windows:

```bat
build-standalone.bat
```

The normal template build produces the readable single HTML, self-extracting HTML, and the repository-root generated copy.

## Browser support

Target: current Chrome, Edge, Firefox, Safari, Android Chrome, and iOS Safari. Direct `file://` opening is required.
